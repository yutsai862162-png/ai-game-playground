## 本輪修正

原本的 PNG adapter 在圖片完成載入後，沒有通知只畫一次的首頁重繪。模擬圖片延遲 1.6 秒時，即使圖片已經到齊，首頁仍顯示 Canvas 舊哥哥。此問題已在 Chromium 和 WebKit 重現並修復。

修正在 `game/hero-assets.js`：

1. 圖片 load/error 後合併排程重繪，目前可見的首頁與超市場景會更新。
2. 記錄目前對話頭像的最後一位角色；慢到的哥哥圖片不覆蓋下一位說話者。
3. 16 張行走圖齊全才一起切換，避免同一段步行在新圖與舊圖間閃爍；缺圖則沿用可玩的 Canvas 版本。
4. 提供唯讀 `HeroAssets.status()` 載圖診斷資訊。
5. 不改圖片原始位元組，不改人物輸入、移動、碰撞、任務或存檔狀態。

## 執行方式與限制

測試在 GitHub Actions Linux runner 上啟動 HTTP 伺服器，載入完整 `game/index.html`、真實引擎、劇情與 PNG。沒有用繪圖替身代替遊戲。

使用 Playwright 1.56.1，分別執行 Chromium 和 WebKit，採 iPhone 13 mobile profile 與 844×390 橫式 viewport；缺圖案例使用 568×320。

- 開始、互動、對話、選項、背包和存檔按鈕：瀏覽器模擬觸控。
- 方向鍵連續按住／放開：瀏覽器滑鼠指標事件。
- 完整路線的逐格導航：實際鍵盤按鍵；讀取正式 findPath 來規劃路線，沒有 teleport、直接呼叫劇情或寫入任務狀態。
- 透過監測並轉呼叫真實 drawImage，確認地圖、頭像和超市使用 `assets/bro/` 的 PNG。
- **以上不是實體 iPhone、實體 Safari、人工手感或效能測試。**
