# CI 保護與家人原圖最小需求

本輪只做本機 CI／測試修改及素材規格核對；沒有推送、觸發遠端 Actions、部署或另行取得 Library 圖片。既有家人配置與隱形方向鍵成果保留。

## CI 改動

`.github/workflows/check-hero-integration.yml` 現在涵蓋 `gpt/hero-art-integration` 與 `gpt/family-integration` 的 push，以及目標為 main／這兩分支、涉及 game／tests／本 workflow 的 pull request。使用 `pull_request` 而非高權限 `pull_request_target`，權限仍是 `contents: read`。公共 HTTPS 預覽 workflow 未擴張到家人分支，這裡的新檢查只服務 loopback 測試。

移除的是整份 `game/game.js` 與舊提交的 `cmp`，替換成 `tests/protected-contracts.cjs`：

- 以固定核准基底 `bb844f9dd413c6a00e257d6863e2602662da42df` 取原始 blob。CI 保留 `fetch-depth: 0`，不把目前分支當成自己的核准標準。
- 比對移動速度、轉身延遲、方向與按鍵映射；保護 stepFrom／walkable／Input.dir，以及方向更新的死區、搖桿比例、遲滯和 CSS 原觸控區範圍。pointerdown 的多指 ownership 邏輯及畫面 opacity 不被整檔鎖死。
- 將目前哥哥 manifest 與核准 manifest 比對，再逐張用核准 SHA-256 驗證 22 PNG，防止同時改 PNG 和 manifest 就繞過檢查。
- 執行真實 Story 互動函式的鞋櫃、房間、冰箱、媽媽、妹妹、爸爸、沙發、重複領取及章末鞋子對話；使用替身收集台詞、道具、成就與狀態進度，與核准基底比較。表情參數與實際畫面由瀏覽器測試負責。
- `--self-test` 刻意破壞速度、轉身、遲滯、死區、觸控尺寸、鞋子台詞／進度／結尾、PNG、PNG+manifest，共 10 種回歸，確認皆被擋下；不相關的 engine helper 和本次已授權 pointer 改動可通過。

新增進 CI：family-assets 邏輯檢查、family-browser 兩引擎顯示檢查，以及 mobile-layout 六組手機／觸控／对話檢查。保留完整遊戲、走路幾何、Linux kernel 診斷與證據封存。瀏覽器安裝成功後，各套測試不因前一套失敗就被略過；失敗不會變成 success。

## 給素材準備者的最小需求（不必重畫站姿）

先正式取得四张原始 PNG／ZIP，保留完整原始解析度、檔名與位元組，不需要事先製成走路圖集。逐張檢查是否能解碼、背景／透明度、頭頂與腳底是否完整；目前仍未取得，不能預設其尺寸或構圖合格。

|項目|可以完全保留原站姿的最短方案|最低需要確認的畫面／資料|只有堅持全面替換時才新增的需求|
|---|---|---|---|
|爸爸坐姿|新站姿用在標題／角色展示；對話可用原圖的頭肩取景。地圖維持目前坐著看電視的 Canvas 演出，明確標註地圖坐姿尚非新圖。|同一張爸爸原圖即可；實測全身 bounds 和頭肩取景範圍，不戴眼鏡、不加未確認鬍子。原圖若有背景，角色卡可保留背景，不必先去背。|若要求地圖爸爸也完全變成新圖且保留坐姿，才需要背面坐姿＋正面坐姿（章末會轉正面），或另行確認的坐姿合成方案；不能用裁掉腿的站姿冒充。無須走路圖。|
|妹妹方向|地圖採固定正面站姿的圖示式呈現，邏輯方向／互動／位置照舊；說話不切回舊圖。標題與對話沿用同一原圖。這是待原圖到位後實作的方案，目前 adapter 還只允許 down。|原站姿完整輪廓、腳底錨點；允許畫面固定正面。避免左右翻轉造成衣服文字、髮型或配件反轉；頭肩取景需實際看圖。|若要忠實呈現現在預設朝左及互動四方向，才需額外側面／背面靜止姿勢，不需要行走動畫。媽媽互動轉向同樣可採固定站姿方案。|

**比例與對話取景：**原始圖不拉伸；標題／地圖以可見人物 bounds 確認腳底中心與高度。對話頭肩取景須留下頭頂、臉頰和下巴，不直接塞整張全身圖。現有對話框約 76–130 CSS px，DPR 上限 3；若原圖頭肩區解析度不足，再回報具體不足，不能先要求重畫整組。大嫂沒有現成台詞，所以本輪不必為她準備六張表情。

**最低可發布範圍必須說清楚：**四張站姿均在正式遊戲入口可見、父母妹妹對話可辨認、地圖新舊範圍列明，手機測試通過。若爸爸地圖保留舊坐姿，稱「站姿／對話整合版」，不要稱「四人全部場景替換完成」。無論採哪個方案，哥哥及鞋子劇情維持核准內容。
